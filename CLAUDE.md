This file provides guidance to Claude Code (claude.ai/code) when
working with code in this repository.

## Overview

**nlmixr2plot** is a pure-R package (no compiled code) that provides
'ggplot2' plotting methods for 'nlmixr2' objects: goodness-of-fit plots
for fits, `augPred()` plots, trace plots, visual predictive checks
(VPCs), and automatic compartment diagrams of 'rxode2'/'nlmixr2' models.
It depends on 'rxode2', 'nlmixr2est' and 'nlmixr2extra' for model
handling and simulation; it has reverse dependencies (babelmixr2,
nlmixr2, shinyMixR -- see `cran-comments.md`).

## Build and Development Commands

### Install / Document
```r
devtools::install()   # or from the shell: R CMD INSTALL .
devtools::document()  # regenerates man/ and NAMESPACE from roxygen
```

`NAMESPACE` and `man/*.Rd` are generated by roxygen2 (markdown enabled);
never edit them by hand.

### Run Tests
```sh
NOT_CRAN=true Rscript -e "devtools::test()"
# Single file: filter is the basename without "test-" and ".R"
NOT_CRAN=true Rscript -e "devtools::test(filter='model-diagram')"
NOT_CRAN=true Rscript -e "devtools::test(filter='vpc-data')"
```

Most test files fit real nlmixr2 models (with `nlmixr2data` data), so the
full suite is slow. Many tests need Suggests packages (`nlmixr2data`,
`vpc`, `tidyvpc`, `DiagrammeR`, `dplyr`, `withr`) and skip without them.

## Architecture

All code lives in `R/`:

| File | Purpose |
|------|---------|
| `R/plot.nlmixr2.R` | `plot.nlmixr2FitData()` goodness-of-fit plots (DV/PRED/IPRED, residuals, per-endpoint via `plotCmt()`), `.setupPlotData()`, `traceplot()` generic and methods |
| `R/plot.bsv.R` | Between-subject-variability plots (eta QQ, eta correlation, eta vs covariate) used by `plot(fit, covariate = ...)` |
| `R/plot.nlmixr2AugPred.R` | `plot.nlmixr2AugPred()` (paginated individual plots, `log = "x"/"y"/"xy"`) |
| `R/vpcPlot.R` | `vpcPlot()`, `vpcPlotTad()`, `vpcCens()`, `vpcCensTad()` and the observed/simulated data setup helpers (`.vpc*`) |
| `R/modelDiagram.R` | `modelGraph()`, `modelDiagram()`, `plot.rxUi`/`plot.rxode2`/`plot.nlmixr2ModelGraph`, `print.nlmixr2ModelGraph`; internals use the `.md*` prefix |
| `R/reexports.R` | Re-exports `geom_cens`, `geom_amt`, `stat_cens`, `stat_amt` from rxode2 |
| `vignettes/model-diagrams.Rmd` | "Automatic model diagrams" vignette |

### Plot return values

Fit plots, BSV plots and `augPred()` plots return `ggtibble::gglist`
objects (built with `ggtibble::new_gglist()` / `as_gglist()`), often named
and nested. Keep that structure when adding plots; tests
(`test-gglist-integration.R`) rely on it.

### VPC backends

`vpcPlot()` has `method = c("vpc", "tidyvpc")`; when not supplied it uses
'vpc' if installed, otherwise 'tidyvpc'. Both are Suggests, so guard any
use with `requireNamespace()`. `fit` may also be a `nlmixr2est::vpcSim()`
simulation. Observed data comes from the original (or supplied `data`)
dataset; records with `MDV = 1` or missing `DV` are dropped, and the
matching simulated records must be dropped too so observed/simulated rows
stay paired. Multiple-endpoint and censored VPCs stratify by endpoint and
match simulated endpoint labels to the observed ones by name.

### Model diagrams

`modelGraph()` parses the model's `d/dt()` equations (the code says
"parsed, not regex matched") into a graph of nodes (compartments with a
role such as dosing/central/effect) and edges (`transfer`, `elimination`,
`input`, `interaction`), detecting dosing compartments from dosing records
and showing `lag()`/`f()`/`rate()`/`dur()` as annotations. `modelDiagram()`
lays it out (`.mdLayout()`) and draws it with one of three engines:
`"DiagrammeR"` (default when installed), `"ggplot2"` (fallback) or
`"dot"` (DOT source string). The default can be set with
`options(nlmixr2plot.diagram.engine = ...)`. DiagrammeR is a Suggests and
must stay conditional. A fitted model keeps its goodness-of-fit `plot()`;
`plot()` of an `rxUi` or compiled `rxode2` model draws the diagram.

## Testing Conventions

- testthat edition 3; files are `tests/testthat/test-*.R`.
- Tests run inside the package namespace: call internals by bare name;
  never use `nlmixr2plot:::`.
- Guard optional dependencies with `skip_if_not_installed()`; guard fits
  that may fail with `skip_if(inherits(fit, "try-error"))`.
- Expensive tests must start with `skip_on_cran()`.
- `tests/testthat.R` partitions the suite for CI:
  - On CRAN/CI it forces single-threaded testing; on CRAN it also sets
    `rxode2::setRxThreads(2L)`.
  - Push/PR CI (`CI=true`, `NOT_CRAN=true`) skips the slow files listed in
    `.slow_batches` (`plots-multiple-endpoints`, `plots-cens`,
    `plots-bsv`).
  - The weekly `slow-tests.yaml` workflow runs each batch via
    `NLMIXR2PLOT_TEST_BATCH=<n>`; the workflow's `batch` matrix must match
    the number of entries in `.slow_batches`.
  - Locally and on CRAN everything runs.
  When a test file grows past a few minutes, move it into a batch.
- `tests/testthat/Rplots.pdf` is a by-product of running tests; do not
  commit changes to it.

## R Code Style

- Exported functions: `camelCase` (`vpcPlot`, `modelDiagram`, `plotCmt`).
- Internal functions and local variables: `.camelCase` with a leading dot
  (`.setupPlotData`, `.vpcSimData`, `.mdLayout`, `.dat0`, `.lst`).
- S3 methods: `generic.class` (`plot.nlmixr2FitData`,
  `traceplot.nlmixr2FitCore`).
- Use `.data$col` (imported from ggplot2) for tidy-eval column references in
  ggplot2 aesthetics.
- Do not use `:::` in package code or tests (CodeFactor flags it).
- Use American English; ASCII only -- no Unicode in R code, roxygen, tests,
  NEWS.md or this file (write `--`, `->`, straight quotes).
- Formatting is owned by air (line width 120, indent 2). air skips calls
  such as `ini()`, `model()`, `rxode2()` and `quote()` so rxode2 model
  syntax (`d/dt(x)`, `lcl <- 1; label("...")`) is left as written.
- lintr: line length 120; `<<-` allowed; `infix_spaces_linter` excludes
  `/`; object-name/usage linters are off. Test files are exempt from a set
  of style linters because they contain rxode2 model syntax.
- Mechanical reformat commits go in `.git-blame-ignore-revs`
  (`git config blame.ignoreRevsFile .git-blame-ignore-revs`).

## CRAN tests: never assert on timing

- Never put a wall-clock timing expectation in a test that can run on CRAN:
  no `expect_lt()`/`expect_true()` on `Sys.time()` differences,
  `system.time()`, `proc.time()`, `bench`/`microbenchmark` results, or any
  other elapsed-time threshold. CRAN check machines are shared and heavily
  loaded, so elapsed time there is random and a timing assertion fails at
  random. Example: nlmixr2plot `test-model-diagram.R` asserted a
  `modelGraph()` call took < 30 s; on CRAN it took 48.4 s and failed.
- Test the result, not the speed. If a speed regression guard is really
  needed, put it only in a test that starts with `skip_on_cran()` (or the
  package's own CRAN skip helper), and never in examples or vignettes.
- Tests that take more than a few seconds should also skip on CRAN.
